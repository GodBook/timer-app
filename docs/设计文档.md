# 计时器（timer-app）设计文档

版本：v1.0（2026-09-15）
状态：已评审（基于 13 项决策问答收口）

---

## 1. 项目概述

一个安卓倒计时应用。核心卖点：**倒计时结束后在任何界面之上弹出悬浮横幅提醒，不手动划掉就一直存在**；锁屏/熄屏时则像系统闹钟一样点亮屏幕全屏提醒。支持多个倒计时并行，可靠地在后台运行。

- **用途**：个人自用，侧载安装，不上架任何应用商店。
- **目标设备**：OPPO/vivo 系手机（ColorOS/OriginOS），Android 16。
- **分发**：GitHub 公开仓库 `timer-app`，通过 Releases 发布 APK，应用内支持手动检查更新。

### 非目标（明确不做）

- 正计时/秒表、闹钟（固定时刻响铃）功能
- 响铃时的「再来 N 分钟」延时按钮
- 自选铃声（固定使用系统默认闹钟铃声）
- 自动检查更新（仅手动）
- 多语言（仅中文界面）

- 悬浮横幅不抢焦点、不拦截横幅区域以外的触摸（其他应用可正常操作）。

```
├─────────────────────────────────────────────────┤

│  SettingsRepository ── 提醒方式等设置（DataStore）   │
│  UpdateChecker ── GitHub Releases API + APK 下载   │
└─────────────────────────────────────────────────┘
```

### 5.2 计时核心设计

**单一事实来源**：每个运行中的计时器只存三个字段决定一切——`endElapsed`（目标 `SystemClock.elapsedRealtime()` 值）、`endWallClock`（对应的墙上时钟，仅用于重启恢复）、`state`（RUNNING / PAUSED / RINGING）。剩余时间永远是 `endElapsed - now` 现算，**不依赖每秒 tick 累减**，因此进程被杀、UI 不在前台都不影响准确性。

- **启动计时器**：写入快照 → `AlarmManager.setExactAndAllowWhileIdle()` 注册到点广播（每个计时器一个独立 `PendingIntent`，requestCode = 计时器 id）→ 启动/更新 `TimerService` 前台通知。
- **暂停**：取消该计时器的闹钟，记录 `remainingMs`，状态置 PAUSED。
- **继续**：按 `remainingMs` 重算 `endElapsed`，重新注册闹钟。
- **取消**：取消闹钟、删除快照；若无其他运行中计时器，`TimerService` 停止自身（stopForeground + stopSelf）。
- **秒级刷新**：`TimerService` 内一个协程 ticker，仅负责刷新通知和 UI 的 StateFlow，与到点判定无关。

### 5.3 到点提醒流程

```
AlarmManager 到点
      │
AlarmReceiver.onReceive
      │  startForegroundService → TimerService（状态置 RINGING）
      ▼
TimerService 判断屏幕状态
      │
      ├─ PowerManager.isInteractive == true 且 KeyguardManager.isKeyguardLocked == false
      │     → ① OverlayBanner 显示顶部悬浮横幅（标明计时器名称）
      │       ② 发一条普通高优先级通知（不带全屏意图，作为通知栏留底）
      │       ③ 按设置响铃/震动
      │
      └─ 熄屏或锁屏
            → ① 发带 fullScreenIntent 的通知 → 系统点亮屏幕，拉起 AlarmActivity
              （setShowWhenLocked + setTurnScreenOn，锁屏之上直接显示）
              ② 按设置响铃/震动
```

**关键规则**：

- 悬浮横幅和全屏响铃页**不同时出现**（按屏幕状态二选一），避免双重提醒。
- 用户在锁屏响铃页「稍后处理」滑掉后**解锁进入桌面时**，若该计时器仍是 RINGING 状态，悬浮横幅补挂上去——保证「不手动划掉就一直存在」跨场景成立（监听 `ACTION_USER_PRESENT`）。
- 多个计时器同时/先后到点：横幅**纵向堆叠**（最新的在上），每条独立上划关闭；全屏响铃页则以列表显示所有正在响的计时器，逐个关闭。
- 响铃/震动是全局单例：只要存在任一 RINGING 计时器就响，最后一个被处理掉才停。
- 划掉横幅 / 在响铃页点关闭 → 该计时器状态终结：停它的铃、删快照、撤对应通知，三端（横幅/响铃页/通知）状态同步，由 `TimerService` 统一分发。

### 5.4 悬浮横幅实现要点

- `WindowManager.addView()`，窗口类型 `TYPE_APPLICATION_OVERLAY`。
- 窗口 flags：`FLAG_NOT_FOCUSABLE | FLAG_LAYOUT_IN_SCREEN`，高度 wrap_content、宽度 match_parent、gravity TOP——只覆盖顶部横条区域，不影响下方应用操作。
- 内容用 `ComposeView` 渲染；需手动为其挂 `LifecycleOwner` / `SavedStateRegistryOwner` / `ViewTreeViewModelStoreOwner`（悬浮窗脱离 Activity，必须自建，这是 Compose 悬浮窗的标准坑）。
- 上划关闭：Compose `detectVerticalDragGestures`，位移超阈值（如 60dp）→ 上移淡出动画 → `removeView`。横幅上同时放一个「停止」按钮作为无手势兜底。
- 横幅内容：计时器名称 + 「倒计时结束」+ 已超时时长（每秒刷新，如「已超时 1:23」，强化紧迫感）。

### 5.5 响铃与震动

- 铃声：`RingtoneManager.getDefaultUri(TYPE_ALARM)`，`MediaPlayer` 播放，`AudioAttributes.USAGE_ALARM`（走闹钟音量通道，媒体静音也能响）。
- 循环模式：`isLooping = true`；「只响一次」模式播完自停；持有 partial `WakeLock` 直至停铃。
- 震动：`VibratorManager`，waveform 循环模式与铃声模式联动。
- 设置项（SettingsRepository）：提醒方式 = 循环响铃+震动（默认）/ 响一次+震动 / 仅震动 / 静音。

### 5.6 重启恢复（F11）

`BootReceiver` 收到 `BOOT_COMPLETED`：读取快照，`elapsedRealtime` 已重置，故用 `endWallClock` 重算——

- 未到点：重算 `endElapsed`，重新注册闹钟，恢复前台服务。
- 关机期间已到点：立即进入 RINGING 流程，提醒文案注明「已于 XX:XX 到时」。

## 6. UI 设计

Material 3，动态取色（Monet），仅中文。共 4 个页面 + 2 个提醒面。

### 6.1 主页：计时器列表

- 顶栏：应用名「计时器」+ 设置入口图标。
- 权限缺失时顶部常驻黄条警告（点击进向导对应步骤）。
- 列表项（卡片）：名称、剩余时间（大字号，每秒刷新）、环形进度、暂停/继续与取消按钮。
- 空状态：引导文案 + 大号「+」。
- 右下 FAB「+」→ 新建页。

### 6.2 新建计时器页

- 时/分/秒三列滚轮（Compose 自绘 picker 或 `NumberPicker` 封装）。
- 名称输入框（默认「计时器 N」）。
- 预设区：横向 chip 列表，点即以该预设开始；长按删除；「保存为预设」按钮把当前滚轮值+名称存为预设。
- 底部主按钮「开始」。

### 6.3 设置页

- 提醒方式（单选：循环响铃+震动 / 响一次+震动 / 仅震动 / 静音）
- 权限状态一览（每项显示已授予/未授予，点击跳系统设置）
- ColorOS 保活设置引导入口
- 检查更新（显示当前版本号）
- 关于（GitHub 仓库链接）

### 6.4 全屏响铃页（AlarmActivity）

- 黑底大字：计时器名称 +「倒计时结束」+ 已超时时长。
- 多计时器同时响时列表展示。
- 底部大号「关闭」滑动条（模仿系统闹钟的滑动关闭，防误触）。
- `setShowWhenLocked(true)` + `setTurnScreenOn(true)`，锁屏之上直接显示，无需解锁。

### 6.5 悬浮横幅

- 顶部圆角卡片：⏰ 图标 + 「{名称} 倒计时结束 · 已超时 m:ss」+「停止」按钮。
- 上划关闭；多条纵向堆叠。

## 7. 数据模型

```kotlin
// 运行中计时器快照（DataStore JSON list）
data class TimerSnapshot(
    val id: Int,
    val name: String,
    val totalMs: Long,
    val endElapsed: Long,     // SystemClock.elapsedRealtime() 目标值
    val endWallClock: Long,   // System.currentTimeMillis() 目标值（重启恢复用）

// 预设（DataStore JSON list）
data class Preset(val id: Int, val name: String, val durationMs: Long)

// 设置（DataStore Preferences）
enum class AlertMode { LOOP_SOUND_VIBRATE, ONCE_SOUND_VIBRATE, VIBRATE_ONLY, SILENT }
```

## 8. 应用内更新设计（F9）

数据源：GitHub Releases。发版约定：tag 形如 `v1.2.0`，`versionName` 与 tag 一致，Release 附件上传 `timer-app-v1.2.0.apk`。

流程（设置页点「检查更新」触发）：

1. `GET https://api.github.com/repos/<owner>/timer-app/releases/latest`（无需鉴权，注意 60 次/小时的匿名限额——手动触发场景足够）。
2. 解析 `tag_name`，与 `BuildConfig.VERSION_NAME` 做语义化版本比较。
3. 无新版 → Toast「已是最新版本」；网络失败 → Toast 报错（国内直连 GitHub 可能不通，属预期，提示用户重试或挂代理）。
4. 有新版 → 对话框显示版本号 + Release Notes（`body` 字段）→ 用户确认。
5. OkHttp 下载 APK 到 `cacheDir`，对话框内显示进度。
6. `FileProvider` 生成 uri，`ACTION_VIEW` + `application/vnd.android.package-archive` 唤起系统安装器；未授予「安装未知应用」则先跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES`。

**签名注意**：应用内更新要求新旧 APK 签名一致。首次构建生成的 keystore 必须妥善保存（**不提交进仓库**，路径写进 `.gitignore`），丢失则老用户只能卸载重装。

## 9. ColorOS / OriginOS 保活方案

系统级查杀无法用代码根治，策略 = 尽量豁免 + 引导用户设置 + 依赖 AlarmManager 兜底（即使前台服务被杀，已注册的精确闹钟仍由系统触发，到点广播会重新拉起服务——这是本设计可靠性的底线保障）。

设置页「保活引导」提供逐步说明并尽可能直接跳转：

1. **允许自启动与关联启动**：跳转应用详情页（`ACTION_APPLICATION_DETAILS_SETTINGS`），指引进入「自启动管理」开启。
2. **电池 → 无限制**：应用详情页内「电量使用」设为「允许完全后台行为/无限制」。
3. **锁定后台卡片**：最近任务界面下拉本应用卡片 → 锁定（图文说明，无法跳转）。
4. **电池优化豁免**：App 内直接弹 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 对话框。

## 10. 边界情况与风险

| 场景 | 处理 |
|------|------|
| 悬浮窗权限被拒 | 降级：解锁态到点只发高优先级通知（heads-up），主页黄条持续提示 |
| 全屏通知权限被用户关闭 | 降级：锁屏态到点发普通通知+响铃，主页黄条提示 |
| 通知权限被拒 | 前台服务无法可见运行，向导中标红强提示，功能核心依赖，视为必须项 |
| 响铃中用户直接从最近任务划掉 App | 闹钟已注册不受影响；RINGING 中服务被杀 → 通知仍在；重开 App 恢复 RINGING 界面态 |
| 到点时正在通话 | `USAGE_ALARM` 音频焦点策略交给系统（会压低/延后），震动照常 |
| 用户修改系统时间 | 计时基于 `elapsedRealtime`，不受影响 |
| 计时跨天/超长（>24h） | 滚轮上限 23:59:59，够用；不做多天计时 |
| 同 id PendingIntent 冲突 | requestCode 用自增计时器 id，`FLAG_IMMUTABLE | FLAG_UPDATE_CURRENT` |
| GitHub API 限流/不可达 | 手动触发 + 失败 Toast，不重试不缓存 |

## 13. 发布流程

1. GitHub 新建公开仓库 `timer-app`，推送源码（keystore 与签名配置不入库）。
2. 本地 `assembleRelease` 出签名 APK。
3. 打 tag `vX.Y.Z` → GitHub Release → 上传 `timer-app-vX.Y.Z.apk`，填写更新说明（App 内更新对话框会展示）。
4. `versionCode` 每次发布 +1，`versionName` 与 tag 保持一致。
